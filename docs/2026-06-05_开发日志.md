### 2. `main.py` — 交互式 CLI

- **改动**：将 `url` 从必填位置参数改为可选（`nargs="?"`）
- **原因**：方便在 VS Code 中直接按 F5 调试，无需修改 `launch.json` 传参
- **行为**：
  - 不传参数 → 启动后交互式提示输入 URL 和输出目录
  - 传参数 → 保持原有命令行用法，兼容脚本调用

### 3. `downloader.py` — 标题匹配修复

**问题现象**：
```
找到 8 个 <div align='right'> 容器
提取到 0 个有效 PDF 分组
```

**根因分析**：
- 原标题正则 `[^\d]+大$` 硬性要求出处以"大"结尾（如 `近畿大`）
- 实际页面中出处为 `センター追試`、`センター試験`，不以"大"结尾，导致标题匹配全部失败

**修复**：
- `TITLE_SEARCH_PATTERN`: `(\d{8}.+?\d{2}[\d]{2,})` → `(\d{8}.+?\d{2}[^\d]{2,})`
- 同时兼容旧格式（大学名）和新格式（考试名）

**其他改进**：
- 增加 INFO 级别诊断日志，每个 `<div>` 和 `<a>` 都会输出 `href`/`text`/`innerHTML` 等关键信息，方便后续调试
- 支持 `<div align="RIGHT">` 大写属性匹配
- 链接识别策略：先通过 `<p2>問題</p2>` / `<p3>解答</p3>` 标记识别，失败则 fallback 到文件名模式匹配

### 4. `parser.py` — 命名规则迭代

**第一次尝试**（已废弃）：
- 文件名中加入 `第{n}题`，如 `2019近畿大_データの分析_第19题_问题.pdf`
- **废弃原因**：用户反馈需要更唯一的标识

**最终方案**：
- 从 8 位序号中拆分：
  - 前 2 位 → 年份（补全为 4 位）
  - 后 6 位 → **识别码**（确保文件名唯一，避免覆盖）
- 新命名格式：`{补全年份}{出处}_{知识点}_{识别码}_问题.pdf`
- 示例：`19112202` → 年份 `19` + 识别码 `112202` → `2019近畿大_データの分析_112202_问题.pdf`

### 5. 解析正则更新

| 项目 | 修改前 | 修改后 |
|------|--------|--------|
| 正则 | `^(\d{8})(.+?)(\d{2})([^\d]+大)$` | `^(\d{8})(.+?)(\d{2})(.+)$` |
| 出处限制 | 必须以"大"结尾 | 任意字符串 |
| 兼容性 | 仅大学名 | 大学名 + 考试名（センター試験等） |
