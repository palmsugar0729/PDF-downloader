## 讨论脉络

### 1. 项目形态 — CLI vs GUI

- **背景**：`needs.md` 写的是"桌面程序"
- **结论**：采用 **CLI 命令行工具**
- **理由**：用户自用，效率优先；开发成本低；可组合性强；不锁死后续加 GUI 的可能

### 2. PDF 命名规则

- **目标站点**：`https://mikiotaniguchi.com/main/sm/smmain.htm`
- **页面结构**：题目序号（左）+ 截图（中）+ `<div align="right">`（右，含 PDF 链接和标题文字）
- **标题样本**：`19112202データの分析19近畿大`
- **标题格式**：`{8位序号}{知识点}{2位年份}{出处}`
- **解析正则**：`^(\d{8})(.+?)(\d{2})([^\d]+大)$`
- **文件名格式**：`{补全年份}{出处}_{知识点}_问题.pdf` / `_答案.pdf`
- **年份补全**：`≤ 26` → `20xx`，`> 26` → `19xx`
- **保存路径**：`{输出目录}/{出处}/`
- **PDF 区分**：
  - 问题 PDF：`XXXXXXXX.pdf`，不含 `s`，标记 `<p2>問題</p2>`
  - 答案 PDF：`XXXXXXXXs.pdf`，含 `s`，标记 `<p3>解答</p3>`
- **下载条件**：必须同时有"问题 PDF"和"答案 PDF"
- **仅有答案的题目**：暂时跳过，后期考虑截图功能

### 3. "不造成困扰"策略

- **请求间隔**：随机延迟 1~3 秒
- **遵守 robots.txt**
- **设置合理 User-Agent**
- **原则**：遵守规则的前提下尽量快，不过度磨蹭
- **爬取范围**：仅给定单个页面，不跟踪子链接

### 4. 技术栈确认

- **语言**：Python 3
- **爬取引擎**：Selenium + Chrome
- **理由**：页面为 `document.write()` 动态生成，需要浏览器渲染

## 关键决策记录

| # | 决策 | 结论 | 理由 |
|---|------|------|------|
| 1 | 程序形态 | CLI 工具 | 自用、效率优先、开发成本低 |
| 2 | 爬取引擎 | Selenium + Chrome | 目标页面 JS 动态渲染 |
| 3 | 爬取范围 | 单页面，不递归 | 用户手动控制，避免过量 |
| 4 | 下载条件 | 同时有问题+答案 PDF | 确保完整性 |
| 5 | 命名来源 | 从页面标题 text 解析 | 标题包含完整元信息 |
| 6 | 年份补全 | 2 位 → 4 位 | ≤26 → 20xx, >26 → 19xx |
| 7 | 请求策略 | 1~3s 随机延迟 + robots.txt | 友好但不磨蹭 |
| 8 | 代码组织 | 所有代码放 `codes/` | 保持根目录整洁 |
