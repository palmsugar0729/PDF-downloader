## 001 — Pylance 无法解析 `requests` / `webdriver_manager`

**首次发现**：2026-06-05
**状态**：✅ 已解决

### 现象
VS Code 中 `import requests` 和 `from webdriver_manager.chrome import ChromeDriverManager` 报红线，提示 `Pylance: Import "requests" could not be resolved`。

### 根因
VS Code 当前选中的 Python 解释器环境没有安装这些第三方库。通常是因为：
- 系统中安装了多个 Python 版本，VS Code 默认指向了没有装依赖的那个
- 依赖安装在全局环境，但 VS Code 选中了虚拟环境

### 解决方案
1. 确认 VS Code 底部状态栏显示的 Python 解释器路径正确（即安装了依赖的那个）
2. 在正确的环境中执行：
   ```bash
   cd codes
   pip install -r requirements.txt
   ```
3. 如果使用了虚拟环境，确保 VS Code 选中了该虚拟环境的解释器

## 002 — 找到 N 个容器但 0 个有效分组

**首次发现**：2026-06-05
**状态**：✅ 已解决

### 现象
日志显示：
```
找到 8 个 <div align='right'> 容器
提取到 0 个有效 PDF 分组
```

### 根因
标题正则 `[^​\d]+大$` 硬性要求出处以"大"结尾（如 `近畿大`），但实际页面中的出处可能是 `センター追試`、`センター試験` 等，不以"大"结尾，导致标题匹配全部失败。

### 解决方案
- `parser.py` + `downloader.py`：将标题正则放宽为 `(.+)$`，匹配任意字符串作为出处
- 同时增加了更详细的诊断日志，方便后续调试

**涉及提交**：`a06f8c6` 之前的开发迭代

## 003 — `webdriver-manager` 锁文件超时导致崩溃

**首次发现**：2026-06-06
**状态**：✅ 已解决

### 现象
程序启动时直接崩溃，报错：
```
TimeoutError: Timed out waiting for webdriver-manager lock:
C:\Users\<用户名>\.wdm\.wdm-lock-chromedriver-win64
```

Traceback 显示 `webdriver_manager.core.manager._acquire_lock` 在创建锁文件时因 `FileExistsError` 进入等待，最终超时。

### 根因
`webdriver-manager` 为了防止并发下载，会在用户目录下创建文件锁。如果前一次运行异常退出（如强制关闭终端、进程被杀），锁文件不会被清理，导致后续所有运行都因等待锁而超时。

### 临时解决（紧急恢复）
手动删除残留的锁文件：
```bash
rm "$USERPROFILE/.wdm/.wdm-lock-chromedriver-win64"
```

### 根本解决（已合并到代码）
- 不再使用 `webdriver-manager` 动态下载 chromedriver
- 改为引用本地固定的 `chromedriver.exe`
- 代码修改：`codes/downloader.py` 中移除 `ChromeDriverManager().install()`，改用 `Service(driver_path)`

## 004 — chromedriver 从 Google 下载极慢/假死

**首次发现**：2026-06-06
**状态**：✅ 已解决

### 现象
程序卡在：
```
[WDM] About to download new driver from https://storage.googleapis.com/...
[WDM] Driver downloading response is 200
```
之后长时间无响应，CPU 和网络占用都很低，看似"假死"。

### 根因
`webdriver-manager` 需要从 Google Cloud Storage (`storage.googleapis.com`) 下载 chromedriver（约 30-50 MB）。在国内访问该域名速度极慢或频繁断连，导致下载过程卡住。

### 临时解决
- 开启代理/梯子后再次运行，可正常下载

### 根本解决（已合并到代码）
- 提前将 chromedriver 下载好，放在项目根目录 `chromedriver-win64/chromedriver.exe`
- 代码中直接引用本地文件，完全绕过网络下载流程
- 与 **003** 共用同一套修复方案

**涉及提交**：本次修改（待提交）

## 005 — Chrome 更新后 chromedriver 版本不匹配（预期问题）

**首次发现**：—（尚未发生）
**状态**：⚠️ 待观察

### 预期现象
Chrome 浏览器自动更新后，启动程序时报错：
```
selenium.common.exceptions.SessionNotCreatedException:
This version of ChromeDriver only supports Chrome version X
```

### 根因
本地固定的 `chromedriver.exe` 版本与系统已安装的 Chrome 浏览器版本不一致。Selenium 要求两者主版本号必须匹配。

### 解决方案
1. 查看报错信息中提到的 Chrome 版本号（如 `148`）
2. 访问 [Chrome for Testing 下载页](https://googlechromelabs.github.io/chrome-for-testing/)
3. 找到对应版本的 `chromedriver-win64.zip`，下载并解压
4. 用新的 `chromedriver.exe` 覆盖项目中的 `chromedriver-win64/chromedriver.exe`
5. 无需修改任何代码

### 预防建议
- 在 `README.md` 或运行脚本中添加版本检查提示
- 未来可考虑封装一个版本检查和自动提醒的小脚本
