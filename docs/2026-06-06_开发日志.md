## 一、今日完成的工作

### 1. 修复：`webdriver-manager` 锁文件超时导致程序崩溃

**问题现象**：
```
TimeoutError: Timed out waiting for webdriver-manager lock:
C:\Users\palmsugar\.wdm\.wdm-lock-chromedriver-win64
```

**根因分析**：
- `webdriver-manager` 会在用户目录下创建文件锁，防止并发下载 chromedriver
- 如果前一次程序异常退出（强制终止、未捕获的异常），锁文件不会被清理
- 下次启动时，新进程等待锁释放，默认超时约 60 秒，超时后直接抛异常退出

**修复方案**：
- 不再使用 `ChromeDriverManager().install()` 动态下载
- 改为使用本地固定的 `chromedriver.exe`，路径写死在代码中
- 使用相对路径计算，确保在不同运行环境下都能正确定位：
  ```python
  driver_path = os.path.join(
      os.path.dirname(os.path.dirname(os.path.abspath(__file__))),
      "chromedriver-win64",
      "chromedriver.exe",
  )
  service = Service(driver_path)
  ```

**涉及文件**：
- `codes/downloader.py`：移除 `webdriver_manager` import，修改 `_setup_driver()` 方法

### 2. 修复：chromedriver 下载极慢/假死

**问题现象**：
程序卡在：
```
[WDM] About to download new driver from https://storage.googleapis.com/...
[WDM] Driver downloading response is 200
```
之后长时间无响应（> 10 分钟）。

**根因分析**：
- `webdriver-manager` 需要从 Google Cloud Storage (`storage.googleapis.com`) 下载 chromedriver
- 国内网络访问该域名极慢或连接不稳定
- 即使挂了代理可以访问，但默认流程下用户体验差（首次运行必须等待下载几十 MB）

**修复方案**：
- 与问题 1 合并处理：提前将对应版本的 `chromedriver.exe` 放到项目根目录 `chromedriver-win64/` 下
- 代码中直接引用本地文件，完全绕过网络下载

**版本信息**（本次放置的 chromedriver）：
- Chrome 版本：`148.0.7778.178`
- 对应 chromedriver：`148.0.7778.178`
- 放置位置：`chromedriver-win64/chromedriver.exe`
